00Как читать любую команду

Прогресс урока:
0/0
📖 Теория

Терминал — окно, где ты управляешь компьютером текстом, а не мышкой. Shell («оболочка») — программа-переводчик: читает твою строку и запускает нужное. Bash (Bourne again shell) — самый популярный shell. Представь официанта: ты говоришь словами-командами, он несёт их «на кухню» (системе) и приносит результат.

Справа у тебя всегда стоит учебный терминал — безопасная песочница. Кнопка «⌨ Терминал» сверху скрывает и открывает его. Зелёные кнопки в уроках сами вставляют команду в терминал.

👁 Визуализация — анатомия команды
wcКОМАНДА
что делаем -lФЛАГ
как делаем app.logАРГУМЕНТ
над чем делаем
  • Команда — имя программы, почти всегда сокращение английского слова.
  • Флаг (опция, ключ) — с - (буква) или -- (слово). Меняет поведение: «считай не слова, а строки».
  • Аргумент — объект: файл, папка, число, текст.
💡 Короткие флаги склеиваются: ls -l -a -h = ls -lah. Linux различает регистр: -R и -r — разные флаги, File.txt и file.txt — разные файлы.

✏️ Практика

Запусти справку. Введи help в терминале справа — увидишь всё, что он умеет. Задание отметится само ✓

ПодсказкаЧетыре буквы: h-e-l-p, затем Enter.
⚡ Блиц

Что такое флаг?

Флаг — «настройка» запуска: -l у wc переключает его со слов на строки. Имя программы — команда, файл — аргумент.
🔮 Предскажи

В команде head -n 5 access.log назови команду, флаг и аргумент.

ПодсказкаПервое слово — команда; что с - — флаг; имя файла — объект.
Ответhead — команда («голова», начало файла), -n 5 — флаг со значением (number — число строк), access.log — аргумент.
🐛 Найди ошибку

Новичок написал LS -L и получил «command not found». Две причины?

ОтветLinux различает регистр: команда — ls маленькими, и флаг -l тоже маленький. Правильно: ls -l.
🧩 Вставь пропуск

«Список: подробно + скрытые + размеры по-человечески»: ls -___ (три буквы одним ключом).

Подсказкаlong + all + human.
Ответls -lah

01Навигация: pwd, ls, cd

Прогресс урока:
0/0
📖 Теория

Файловая система Linux — одно большое дерево от корня /. Ты всегда «стоишь» в какой-то папке, как на этаже здания. Три команды: «где я», «что тут», «перейди».

pwd→print working directory→«напечатать рабочую папку» = где я?
ls→list→«список» = что здесь лежит?
ФлагОт словаЧто делает
-llong — длинныйподробно: права, размер, дата
-aall — всепоказать скрытые (имя начинается с точки: .env)
-hhuman — человечныйразмеры в KB/MB вместо байтов
cd→change directory→«сменить папку» = перейди туда
👁 Визуализация — дерево и спец-адреса 
/
└── home/
    └── devops/        ← ты здесь (домой ведёт ~)
        ├── notes.txt
        ├── servers.txt
        ├── .env       (скрытый: виден только ls -a)
        ├── logs/      app.log, error.log
        └── scripts/   deploy.sh

cd logs     # вниз, в папку logs (относительный путь)
cd ..       # .. = на этаж ВВЕРХ (родитель)
cd .        # . = текущая папка («остаться»)
cd ~        # ~ = домой (cd без аргумента — тоже домой)
cd /        # / = самый корень дерева
💡 Абсолютный путь начинается с / и работает откуда угодно. Относительный — от текущей точки: logs, ../scripts.
▶ Повтори:
✏️ Практика
⌨ В терминалеждёт команду

Узнай, где ты находишься. Одна команда из трёх букв.

Подсказка«Print working directory».
Ответpwd → /home/devops
⌨ В терминалеждёт команду

Найди скрытый файл. В домашней папке спрятан файл, который обычный ls не показывает. Выведи его на экран.

ПодсказкаФлаг all.
Ответls -a (или ls -la) → появится .env.
⌨ В терминалеждёт команду

Спустись в папку logs. Проверь себя: приглашение терминала станет :~/logs$.

Ответcd logs
⌨ В терминалеждёт команду

Вернись домой из logs. Сначала убедись, что ты в logs (предыдущее задание), потом вернись в /home/devops.

ПодсказкаТри способа: этаж вверх, символ дома, или cd без аргумента.
Ответcd .. или cd ~ или просто cd.
⚡ Блиц

Что делает cd без аргументов?

cd = cd ~ — домой. Удобно, когда «заблудился».
🔮 Предскажи

Ты в /home/devops/logs. Куда приведёт cd ../scripts? А потом cd ../..?

ОтветСначала /home/devops/scripts (вверх, потом вниз). Затем два этажа вверх → /home.

02Смотрим файлы: cat, less, head, tail, wc

Прогресс урока:
0/0
📖 Теория
cat→concatenate→«склеить» = вывалить всё содержимое на экран

cat notes.txt — показать файл целиком; cat a.txt b.txt — склеить два подряд. Для огромных логов неудобен — всё пролетает мимо глаз. Тогда less: листай стрелками, /слово — поиск, q — выход.

head→head = голова→первые строки (по умолчанию 10)
tail→tail = хвост→последние строки (по умолчанию 10)

Флаг -n (number — число) задаёт сколько: head -n 3. Можно короче: head -3.

👁 Визуализация — что вырежет head/tail (файл app.log) 
2026-01-01 INFO Server started      ← head -n 3 берёт ЭТИ три
2026-01-01 WARN High memory
2026-01-01 ERROR Connection failed
2026-01-02 INFO Request ok
2026-01-02 ERROR Timeout            ← tail -n 2 берёт ЭТИ две
2026-01-02 INFO Done
💡 tail -f (follow — «следуй») — любимая команда DevOps: смотрит, как лог растёт вживую. Остановить — Ctrl+C. В песочнице прилетят новые строки!
wc→word count→«ворд каунт», счётчик слов. Но считает не только слова:
ФлагБуква отСчитает
-llines — строкиколичество строк
-wwords — словакусочки текста через пробелы
-ccount of bytesсимволы/байты

Читаем целиком: wc -l app.log = «счётчик (word count), режим строк (lines), файл app.log» → сколько строк в app.log. Без флагов wc выдаёт три числа: строки, слова, байты.

▶ Повтори:
✏️ Практика
⌨ В терминалеждёт команду

Посчитай строки в logs/app.log. Должно получиться 6.

Подсказкаwc + флаг «lines» + путь к файлу.
Ответwc -l logs/app.log
⌨ В терминалеждёт команду

Покажи ровно 2 последние строки app.log. Ни больше, ни меньше.

Ответtail -n 2 logs/app.log (или tail -2 logs/app.log)
⌨ В терминалеждёт команду

Посмотри лог вживую. Запусти слежение за app.log — и увидишь, как прилетят две новые строки.

ПодсказкаФлаг follow.
Ответtail -f logs/app.log
⚡ Блиц

Сколько строк покажет head file без -n?

И head, и tail по умолчанию — 10 строк. Все — это cat.
🔮 Предскажи

Что выведет wc -l servers.txt? А wc -w servers.txt? (В файле 4 строки вида web:prod:10.0.0.1.)

ПодсказкаПробелов внутри строк нет — значит каждая строка это одно «слово».
ОтветОба дадут 4: строк 4, и «слов» тоже 4 — разделителей-пробелов нет. Проверь в терминале!
🐛 Найди ошибку

Хотели первые 5 строк, написали tail -n 5 app.log. Что не так?

Ответtail — хвост, конец. Начало — это head -n 5 app.log.

03Пайпы и редиректы — сердце Bash

Прогресс урока:
0/0
📖 Теория

У каждой команды есть вход (stdin) и выход (stdout). Обычно выход летит на экран, но его можно передать следующей команде или в файл. Это конвейер на заводе: деталь (текст) едет от станка к станку.

|→pipe→«труба»: выход левой команды = вход правой
👁 Визуализация — нажми ▶ и посмотри, как данные текут

cat logs/app.log

│

grep ERROR

пропускает только ERROR
│

wc -l

0
считает строки
Нажми ▶ — увидишь, какие строки grep отбросит, а какие дойдут до счётчика.
>→redirect→перенаправить в файл (ПЕРЕЗАПИСАТЬ!)
>>→append→дописать в конец (старое сохраняется)
# в notes.txt было 3 строки. Выполняем: echo "new" ...
>  notes.txt  →  в файле ОДНА строка "new"    (старые 3 стёрты!)
>> notes.txt  →  4 строки: старые 3 + "new"  (дописали)
⚠️ > стирает содержимое без вопросов и без корзины. Хочешь добавить — только >>.
▶ Повтори:
✏️ Практика
⌨ В терминалеждёт команду

Собери конвейер из трёх команд. Получи число строк с ERROR в app.log: вывести → отфильтровать → посчитать. Две трубы |, ответ 2.

Подсказкаcat … | grep … | wc …
Ответcat logs/app.log | grep ERROR | wc -l
⌨ В терминалеждёт команду

Сохрани ошибки в файл. Создай errors.txt, где будут только строки с ERROR из app.log — без INFO и WARN.

Подсказкаgrep умеет и сам читать файл, а > сохранит вывод.
Ответgrep ERROR logs/app.log > errors.txt. Проверь: cat errors.txt.
⌨ В терминалеждёт команду

Допиши строку в notes.txt, не стирая старое. В файле 3 строки (начинается с «todo»). Добавь любую свою — должно стать минимум 4, и «todo» обязано выжить.

ПодсказкаДва знака «больше», не один.
Ответecho "моя строка" >> notes.txt
⚡ Блиц

Чем опасен > по сравнению с >>?

> = «начни файл заново», >> = «допиши в конец». Классическая авария: хотели дописать лог, а стёрли его.
🔮 Предскажи

Что напечатает head -n 2 servers.txt | wc -l?

Ответ2: head отрезает 2 строки, wc считает уже их. Конвейер работает слева направо.
🐛 Найди ошибку

Команда wc -l | logs/app.log не работает. Что перепутали?

Ответ| соединяет две команды, а справа — файл. Либо wc -l logs/app.log, либо cat logs/app.log | wc -l.

04grep — фильтр строк

Прогресс урока:
0/0
📖 Теория
grep→global regular expression print→«напечатать строки, совпавшие с шаблоном»

Представь сито: высыпаешь текст — проваливаются только строки с нужным словом. Остальное исчезает. Это grep.

grepфильтруй -iignore case
без регистра "ERROR"что ищем app.logгде ищем
ФлагОт словаЧто делает
-iignore caseERROR = error = Error
-vinvert — наоборотстроки, где шаблона НЕТ
-ccount — счёттолько число совпавших строк
-nnumber — номерпоказать номера строк

Мини-шаблоны: ^ — начало строки ("^2026"), $ — конец ("Done$"), . — любой символ.

▶ Повтори:
✏️ Практика
⌨ В терминалеждёт команду

Найди предупреждение. Выведи строку с WARN из app.log.

Ответgrep WARN logs/app.log
⌨ В терминалеждёт команду

Посчитай ошибки одним grep. Без wc и без самих строк — только число 2.

ПодсказкаФлаг count.
Ответgrep -c ERROR logs/app.log
⌨ В терминалеждёт команду

Покажи всё, КРОМЕ скучного. Выведи строки app.log без слова INFO — должно остаться 3 строки.

ПодсказкаФлаг invert — «наоборот».
Ответgrep -v INFO logs/app.log
⚡ Блиц

В файле строки Error и ERROR. Что найдёт grep ERROR file?

Без -i grep различает регистр. Обе найдёт grep -i error.
🐛 Найди ошибку

Хотели строки, начинающиеся с даты: grep 2026-01-02$ logs/app.log — пусто. Почему?

Ответ$ — «конец строки», а дата в начале. Нужно grep "^2026-01-02" logs/app.log.
🧩 Собери

Строки с ERROR или WARN одной командой.

Ответgrep -E "ERROR|WARN" logs/app.log → 3 строки. В песочнице сработает и без -E.

05sort, uniq, cut — конвейер обработки

Прогресс урока:
0/0
📖 Теория
sort→sort→«сортировать» строки (по умолчанию по алфавиту)
ФлагОт словаЧто делает
-rreverseв обратную сторону
-nnumericкак числа: 2 < 10 (без него «10» < «2»!)
-uuniqueсразу выбросить дубликаты
uniq→unique→«юник»: убирает повторы, стоящие ПОДРЯД
⚠️ Главная ловушка: uniq видит только соседние дубли. «web, db, web» он не схлопнет. Поэтому всегда: sort | uniq. Флаг -c (count) добавит счётчик.
cut→cut→«резать»: вырезать нужную колонку
👁 Визуализация — как cut видит строку 
строка:  web : prod : 10.0.0.1
         -f 1  -f 2   -f 3      разделитель -d ":" (delimiter)

cut -d ":" -f 1 → web        # field 1: тип сервера
cut -d ":" -f 2 → prod       # field 2: среда
cut -d ":" -f 3 → 10.0.0.1   # field 3: IP
▶ Повтори:
✏️ Практика
⌨ В терминалеждёт команду

Сколько серверов каждого типа? Тип — 1-я колонка servers.txt. Получи список со счётчиками: «1 cache, 1 db, 2 web». Три команды в конвейере.

Подсказкавырезать → сгруппировать → посчитать повторы.
Ответcut -d ":" -f 1 servers.txt | sort | uniq -c
⌨ В терминалеждёт команду

Уникальные среды по алфавиту. 2-я колонка servers.txt: получи ровно dev, prod, stage — по одному разу, на отдельных строках.

Подсказкаcut → sort с флагом unique (или sort | uniq).
Ответcut -d ":" -f 2 servers.txt | sort -u
⚡ Блиц

Почему uniq servers.txt не убрал повтор «web»?

Строки web разделены другими — uniq их не видит. Лечится: sort | uniq.
🔮 Предскажи

Строки «10», «2», «33». Что даст sort, а что sort -n?

Ответsort (по символам): 10, 2, 33. sort -n (по числам): 2, 10, 33. Для чисел всегда -n!
🧠 Сценарий

Найди самый частый IP (3-я колонка): цепочка из cut / sort / uniq / sort / head?

Подсказкавырезать → сгруппировать → посчитать → по убыванию числа → первый.
Ответcut -d ":" -f 3 servers.txt | sort | uniq -c | sort -nr | head -n 1 — классика собеседований!

06awk и sed — тяжёлая артиллерия

Прогресс урока:
0/0
📖 Теория
awk→Aho, Weinberger, Kernighan→фамилии авторов. Язык для колонок

awk сам режет строку на колонки и называет их $1, $2… («доллар один» — первая). $0 — вся строка. Программа в { } выполняется для каждой строки.

awk '{print $1}' servers.txt        # 1-е слово каждой строки
awk -F ":" '{print $2}' servers.txt # -F = Field separator → среды
awk '/ERROR/ {print $1}' logs/app.log # /ERROR/ = фильтр, печатаем дату
💡 awk ≈ cut, но умеет больше: фильтры /.../, суммы, условия. awk -F ":" ≈ cut -d ":".
sed→stream editor→«стрим эдитор»: меняет текст на лету

Главная команда — замена s/что/на что/: s = substitute («подставить»), флаг g = global — все вхождения в строке, не только первое.

sed 's/prod/PRODUCTION/' servers.txt  # замена В ВЫВОДЕ (файл не тронут!)
sed 's/:/ | /g' servers.txt           # все двоеточия → " | "
sed -i 's/ERROR/OK/g' logs/app.log    # -i = in-place: меняет САМ файл
▶ Повтори:
✏️ Практика
⌨ В терминалеждёт команду

Достань среды через awk. Выведи 2-ю колонку servers.txt (разделитель :) — увидишь prod, prod, stage, dev.

Подсказка-F задаёт разделитель, $2 — вторая колонка.
Ответawk -F ":" '{print $2}' servers.txt
⌨ В терминалеждёт команду

Переименуй среду на лету. Выведи servers.txt так, чтобы вместо prod было PRODUCTION. Сам файл не меняй.

Подсказкаs/старое/новое/
Ответsed 's/prod/PRODUCTION/g' servers.txt
🔮 Предскажи

Что напечатает awk '/ERROR/ {print $1}' logs/app.log?

ПодсказкаФильтр оставит 2 строки с ошибками; $1 — первое слово (по пробелу) — дата.
Ответ2026-01-01 и 2026-01-02 — даты двух ошибок. Проверь в терминале!
🧩 Вставь пропуск

Заменить все web на frontend: sed 's/web/frontend/___' servers.txt

ОтветФлаг g. Без него — только первое вхождение в каждой строке.
🐛 Найди ошибку

Выполнили sed 's/ERROR/OK/g' logs/app.log, открыли файл — ERROR всё ещё там. Почему?

Ответsed изменил только вывод. Файл меняет -i (in-place): sed -i 's/ERROR/OK/g' logs/app.log.

07Файловые операции: touch, mkdir, cp, mv, rm

Прогресс урока:
0/0
📖 Теория
touch→«потрогать»→создать пустой файл (если нет)
mkdir→make directory→создать папку; -p = parents, всю цепочку
cp→copy→копия: оригинал остаётся
mv→move→перенос: оригинал исчезает; им же переименовывают
rm→remove→удалить НАВСЕГДА: корзины нет!
touch report.txt          # пустой файл
mkdir -p backup/2026/nov  # -p создаст все три уровня
cp notes.txt notes.bak    # теперь два файла
mv notes.bak backup/      # перенести в папку
mv report.txt otchet.txt  # переименование = mv
rm -r backup/             # -r = recursive: папку со всем содержимым
☠️ rm -rf / — команда-убийца: -f (force) отключает вопросы. Проверяй путь дважды. В песочнице корень защищён — в жизни защиты нет.
✏️ Практика — мини-квест из трёх шагов
⌨ В терминале · шаг 1ждёт команду

Сделай бэкап. Создай папку backup и скопируй в неё servers.txt.

ПодсказкаДве команды: mkdir, потом cp файл папка/
Ответmkdir backup, затем cp servers.txt backup/
⌨ В терминале · шаг 2ждёт команду

Переименуй копию. Пусть в backup лежит servers.old вместо servers.txt.

ПодсказкаПереименование — это mv куда-то… в то же место.
Ответmv backup/servers.txt backup/servers.old
⌨ В терминале · шаг 3ждёт команду

Убери за собой. Удали папку backup целиком. Без нужного флага получишь «Is a directory».

Ответrm -r backup
⚡ Блиц

Что делает rm -rf папка?

r = recursive (вглубь), f = force (без подтверждений). Корзины нет. Самая опасная комбинация в Linux.
🔮 Предскажи

После cp a.txt b.txt и mv a.txt c.txt — сколько файлов и с какими именами?

ОтветДва: b.txt (копия) и c.txt (бывший a.txt). Оригинал исчез — mv переносит.

08find и which — ищем сами файлы

Прогресс урока:

📖 Теория
find→find = «найти»→ищет ФАЙЛЫ по имени/типу, не текст внутри!

Не путай: grep ищет текст внутри файлов, find — сами файлы в дереве. «Найди все .log» — find. «Найди строки ERROR» — grep.

findищи .откуда
(точка = отсюда) -nameпо имени "*.log"шаблон

which→which = «который/где»→откуда запускается команда: which bash → /usr/bin/bash

✏️ Практика
⌨ В терминалеждёт команду

Найди все логи. Одним find от текущей папки отыщи оба .log файла.

Ответfind . -name "*.log"

Покажи только папки. Никаких файлов в выводе — лишь директории.

Подсказка-type + буква слова directory.
Ответfind . -type d
⌨ В терминалеждёт команду

Где живёт grep? Узнай полный путь к исполняемому файлу команды grep.

Ответwhich grep → /usr/bin/grep
🐛 Найди ошибку

Ищут слово ERROR внутри логов командой find . -name ERROR. Почему пусто?

Ответfind ищет файлы с ИМЕНЕМ «ERROR». Текст внутри ищет grep.
🧠 Сценарий (интервью)

«Найти все .log и посчитать строки в каждом» — какая идея с find?

Подсказкаfind умеет выполнять команду для каждого найденного: -exec команда {} \;
Ответfind . -name "*.log" -exec wc -l {} \; — {} подставляет найденный файл. Interview-классика.

09chmod — права доступа

Прогресс урока:
0/0
📖 Теория
chmod→change mode→«сменить режим» = кому что можно

Права — как бейдж-пропуск: у трёх групп свой доступ. owner (владелец), group (группа), others (остальные).

-rwxr-xr--
│└┬┘└┬┘└┬┘
│ │  │  └─ others: r-- → только читать
│ │  └──── group:  r-x → читать + выполнять
│ └─────── owner:  rwx → всё
└───────── тип: - файл, d папка
БукваОт словаРазрешаетЧисло
rread — читатьсмотреть содержимое4
wwrite — писатьменять/стирать2
xexecute — выполнятьзапускать как программу1

Числовой режим — сумма: rwx=7, r-x=5, rw-=6, r--=4. Три цифры = три группы. Пощёлкай тумблеры:

👁 Интерактив — собери права, получи chmod
r·4w·2x·1 owner group others
-rwxr-xr-x755chmod 755 deploy.sh
пресеты:
▶ История в 4 шага: ← отказ! ← работает 🎉
✏️ Практика
⌨ В терминалеждёт команду

Почини деплой. Скрипт scripts/deploy.sh не запускается (Permission denied). Дай ему право на выполнение и запусти — должен напечатать «Deploy done».

Подсказкаchmod +x путь, затем ./путь
Ответchmod +x scripts/deploy.sh, затем ./scripts/deploy.sh
⌨ В терминалеждёт команду

Запри секрет. Файл .env сейчас могут читать все (644). Сделай так, чтобы читать/писать мог ТОЛЬКО владелец.

Подсказкаrw- --- --- = 6,0,0. Проверь потом: ls -la
Ответchmod 600 .env
⚡ Блиц

Файл с паролями. Какой режим?

600 = rw- --- ---. 777 — дыра, 644 даст прочитать пароль всем.
🔮 Предскажи

Расшифруй 640 по буквам для трёх групп.

Ответrw-r-----: владелец читает+пишет, группа читает, остальные — ничего.
🧠 Сценарий

Почему chmod 777 на проде — плохо, даже если «зато работает»?

ОтветЛюбой пользователь/процесс сможет подменить файл. Правило минимальных прав: только необходимое (755/644/600).

10Процессы и порты: ps, ss, lsof, kill

Прогресс урока:
0/0
📖 Теория

Процесс — запущенная программа. Каждый получает номерок, как в гардеробе — PID (Process ID). А сетевые программы ещё и «занимают» порт — номер двери, по которой к ним стучатся клиенты (веб — 80/443, node-приложения часто — 8080).

ps→process status→фотография списка процессов
ss→socket statistics→«статистика сокетов»: кто какие порты слушает
lsof→list open files→«список открытых файлов» (в Linux всё есть файл, даже порт!)
kill→«убить»→на деле «послать сигнал» процессу по PID
👁 Визуализация — читаем ss -tulpn 
# -t tcp  -u udp  -l listening (слушающие)  -p process (кто)  -n numeric (цифрами)
Local Address:Port   Process
0.0.0.0:22          users:(("sshd",pid=640))     # SSH
0.0.0.0:80          users:(("nginx",pid=812))    # веб
0.0.0.0:8080        users:(("node",pid=1204))    # ← кто занял 8080? node!

# точечный вопрос «кто на порту 8080?»:
lsof -i :8080       # -i = internet: сразу имя процесса и PID
ps aux               # все процессы подробно
ps aux | grep node   # найти конкретный
kill 1204            # TERM (15): «пожалуйста, завершись»
kill -9 1204         # KILL (9): немедленно, без сохранения
💡 Всегда начинай с мягкого kill PID. -9 — крайняя мера. После kill порт освобождается — проверь тем же ss!
▶ Повтори:
✏️ Практика — расследование в 3 шага
⌨ В терминале · шаг 1ждёт команду

Выясни, какой процесс занимает порт 8080. Нужно имя и PID. Подойдёт ss, netstat или lsof.

Подсказкаss -tulpn покажет всех; lsof -i :8080 — точечно.
Ответss -tulpn или lsof -i :8080 → node, PID 1204.
⌨ В терминале · шаг 2ждёт команду

Освободи порт 8080. Вежливо заверши виновника по его PID.

Подсказкаkill + номер из шага 1. Без -9 — сначала пробуем мягко.
Ответkill 1204
⌨ В терминале · шаг 3ждёт команду

Убедись, что порт свободен. Повтори проверку портов — 8080 больше не должен фигурировать.

Ответss -tulpn (строки с 8080 нет) или lsof -i :8080 → пусто.
⚡ Блиц

Чем kill -9 отличается от kill?

Число — номер сигнала: TERM=15 (по умолчанию), KILL=9. Начинают с TERM.
🧠 Сценарий

Сервер тормозит. Порядок действий: чем посмотреть, кто ест ресурсы, и что дальше?

Ответ1) top — самый прожорливый + PID. 2) ps aux | grep имя — уточнить. 3) kill PID; завис намертво — kill -9 PID.

11Ресурсы: df, du, free

Прогресс урока:
0/0
📖 Теория

Аналогия: диск — шкаф (хранит долго), RAM — рабочий стол (быстрый, при выключении пустеет). Три команды — три разных вопроса:

df→disk free→«сколько свободно на дисках целиком?»
du→disk usage→«сколько весит эта папка?»
free→«свободно»→«сколько оперативной памяти?»
df -h          # -h human: гигабайты; столбец Use% — заполненность
du -sh logs/   # -s summary (один итог), -h human → вес папки
free -h        # Mem (RAM) и Swap; смотри столбец available!
💡 Расследование «диск кончился»: df -h (какой раздел полон) → du -sh по папкам (кто весит) → чистим найденное.
▶ Повтори:
✏️ Практика
⌨ В терминалеждёт команду

Проверь заполненность дисков. В понятных гигабайтах. Найди, насколько заполнен корневой раздел (Use%).

Ответdf -h → / заполнен на 70%.
⌨ В терминалеждёт команду

Взвесь папку logs. Один итоговый размер, по-человечески.

Подсказкаdu + summary + human.
Ответdu -sh logs
⚡ Блиц

Что показывает free -h?

free — про RAM. Диск — df/du. CPU — top.
🧠 Сценарий

Алерт: «disk usage 95% на /». Первые две команды?

Ответdf -h — подтвердить; затем du -sh по подозрительным папкам (часто /var/log) — найти пожирателя.
🐛 Найди ошибку

Джун видит «free 1.2Gi» и паникует, что памяти мало. Почему рано паниковать?

ОтветLinux отдаёт свободную память под кэш и мгновенно вернёт её приложениям. Смотреть надо столбец available.

curl→client for URL→браузер без картинки: сходить по адресу, принести ответ

13Bash: переменные, циклы, условия

Прогресс урока:
0/0
📖 Теория

Переменная — подписанная коробка со значением. Кладём: NAME="web01" (без пробелов вокруг =!). Достаём: $NAME — «подставь значение».

NAME="web01"
echo $NAME             # → web01
echo "Сервер: $NAME"   # двойные кавычки подставляют
echo '$NAME'           # одинарные — печатают буквально $NAME
⚠️ NAME = "web01" — ошибка! Bash решит, что NAME — команда. Вокруг = пробелов нет.
👁 Визуализация — цикл for по шагам 
for server in web db cache; do
  echo "Проверяю $server"
done

шаг 1: server=web   → «Проверяю web»
шаг 2: server=db    → «Проверяю db»
шаг 3: server=cache → «Проверяю cache»

«Для каждого server из списка … делай … готово». fi — это if наоборот, конец условия.

mkdir backup && cp notes.txt backup/   # && = «и если успешно»
curl -s http://api/health || echo "лежит!" # || = «или иначе»

Каждая команда возвращает код выхода: 0 = успех, не-0 = ошибка (echo $? покажет). На этом работают && и ||. В песочнице есть команды true (всегда 0) и false (всегда ошибка) — потренируйся.

▶ Повтори:
✏️ Практика
⌨ В терминалеждёт команду

Посчитай строки через переменную. Присвой FILE=logs/app.log, затем выполни wc -l $FILE — должно выйти 6.

ПодсказкаДве команды по очереди.Dollar знак обязателен при чтении.
ОтветFILE=logs/app.log, затем wc -l $FILE
⌨ В терминалеждёт команду

Подставь переменную в текст. Присвой NAME=web01 и напечатай «Сервер: web01» через echo с $NAME в двойных кавычках.

ОтветNAME=web01, затем echo "Сервер: $NAME"
⚡ Блиц

Что значит код выхода 0?

0 = успех. Поэтому && продолжает после нуля, || — после ненулевого.
🐛 Найди ошибку

Почему PORT = 8080 — ошибка, а PORT=8080 — нет?

ОтветС пробелами bash видит команду «PORT» с аргументами. Присваивание — слитно.
🔮 Предскажи

Что напечатает for i in 1 2 3; do echo "n$i"; done?

Ответn1, n2, n3 — по строке на каждый элемент.
🔮 Предскажи

NAME=web: чем отличается echo '$NAME' от echo "$NAME"?

ОтветОдинарные напечатают буквально $NAME, двойные подставят → web.
🧠 Сценарий

Цикл: для каждого из web db cache напечатать «ping $s».

Ответ
for s in web db cache; do
  echo "ping $s"
done

⌨ Задача 1ждёт команду

Ответgrep -c ERROR logs/app.log > count.txt

Подсказкаcat умеет склеивать несколько файлов: cat файл1 файл2 | …
Ответcat logs/app.log logs/error.log | wc -l
⌨ Задача 3ждёт команду

Безопасный бэкап одной строкой. Создай папку safe и скопируй туда servers.txt, но копия должна делаться ТОЛЬКО если папка создалась. Один рядок, оператор &&.

Ответmkdir safe && cp servers.txt safe/
⌨ Задача 4ждёт команду

Список прод-серверов для дежурного. В prod.txt — только строки с prod из servers.txt (их ровно 2).

Ответgrep prod servers.txt > prod.txt
🗣 Блиц-интервью

Объясни вслух за 30 секунд: cat app.log | grep ERROR | wc -l — каждое слово и символ.

Эталон«cat (concatenate) выводит файл; труба | передаёт вывод в grep (global regex print) — оставляет строки с ERROR; вторая труба — в wc (word count) с флагом -l (lines) — счётчик строк. Итог: количество ошибок».
